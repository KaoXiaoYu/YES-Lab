# YES Lab 角色与权限设计

## 账号类型

| 角色 | 身份说明 | 权限范围 |
| --- | --- | --- |
| `TEACHER` | 指导教师 | 系统管理员；拥有全部模块管理权限 |
| `CORE_STUDENT` | 核心学生 | 系统管理员；权限与教师完全一致 |
| `MEMBER` | 正式普通成员 | 编辑自己的个人主页；保留参与测验、写题权限 |
| `VISITOR` | 未加入实验室的注册用户 | 填写自己的报名表、查看自己的招新进度 |

教师与核心学生保留不同角色名称，便于展示和后续规则调整，但当前权限集合相同。

## 项目上下文权限

`PROJECT_MANAGE` 是系统级权限，仅教师和核心学生拥有，用于创建项目、查看全部项目和更换负责人。项目创建后还存在团队内的上下文角色：

- 项目负责人：编辑项目资料和项目主图，修改团队名称，添加/删除成员并设置项目管理员。
- 项目管理员：编辑项目资料、项目主图、进度、成果、链接、指导老师和公开展示开关；不能调整团队成员或更换负责人。
- 项目成员：读取自己参与的项目空间。
- 指导老师：可选且只能选择教师账号；该关联本身不自动授予成员或项目管理员权限。

项目管理员必须同时是项目成员；负责人始终自动保留在成员列表中。系统管理员也可替换项目主图。私有项目主图需要 JWT 且仅项目参与者或系统管理员可读；公开项目接口不返回项目管理员和内部权限判断字段。

## 竞赛成果上下文权限

- 比赛队长：任意实验室成员均可提交，提交者自动成为队长；可修改未认证记录、成员关联、证书和图片。
- 关联成员：可在自己的成员主页展示审核通过的比赛成果，但不能修改比赛记录。
- 系统管理员：审核证书、修改全部比赛资料、设置首页展示和手动顺序，并维护外部新闻引用。
- 公开访客：只读取审核通过的比赛详情和公开图集；证书始终保持私有。

队长不能把负责人身份转给其他成员；如后续需要更换队长，应增加带审计记录的管理员操作，而不是允许普通编辑直接改写。已结束比赛替换证书后会自动撤销首页展示并回到待审核状态。

## 成员固定字段

- 基础信息：姓名、学号/内部编号、专业、班级、年级、头像、内部联系方式。
- 状态：候选、试用、正式、暂停、退出。
- 能力标签：至少一个，由管理员维护。
- 成长数据：总积分、当前排名、测验记录、项目记录、比赛与成果。
- 个人主页：主页标语和白名单富文本介绍。

教师的专业、班级和年级不适用，公开及个人页面也不展示这些字段或积分/排名；其他正式成员应由管理员补齐。

公开成员主页只返回展示所需资料，不返回学号/内部编号和内部联系方式。登录成员在自己的页面可查看这些内部字段，系统管理员可在成员管理页维护它们。

## 招新状态机

```text
报名 → 初筛 → 面试 → 技能测试 → 试用期 → 正式成员
  └────── 任意非终态可进入“未通过” ──────┘
```

- 报名表进入初筛后，游客不能自行修改。
- 面试官只能选择教师或核心学生账号。
- 每次状态变化记录原状态、目标状态、时间、操作账号和备注。
- 只有试用期记录可以一键转为正式成员。
- 转换会保留原招新记录；账号需要重新登录以获取新的成员 JWT 权限。
