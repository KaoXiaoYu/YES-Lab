# 任务到期结算与到期规则 · 需求清单

> 本文是**横切三类任务**的改造需求清单：所有任务统一「到期结算积分 + 到期冻结状态变更」。
> 悬赏任务本体的需求见 [`docs/bounty-task-requirements.md`](bounty-task-requirements.md)；技术设计见 [`docs/task-settlement-design.md`](task-settlement-design.md)。
> 到期结算基础功能已上线。2026-09-26 批准：新手/普通任务截止后仍可审核既有提交，驳回后给予本人 24 小时补交；具体覆盖关系见第 8 节。悬赏规则不变。

## 1. 目标与范围

把三类任务的截止时间统一成**硬边界**，并在到期后做两件事：

1. **到期冻结**：到期之后，成员不能再提交、管理员不能再审核或驳回。任务状态与对象状态从此冻结，唯一允许的动作是**延长截止日期**（补救）与**移除接取者**（悬赏的清理动作）。
2. **到期结算**：到期后由**定时任务自动结算**，给结算那一刻状态为「已完成」的对象发放积分；新手/普通任务截止后仍可审核既有提交，普通任务迟到通过沿用幂等路径计分（见第 8 节）。悬赏仍在到期时冻结。

配套口径：

- **结算后不能驳回**——实际上比这更严：**到期即不能驳回，也不能审核通过**。结算是终局。
- 因此**冻结与结算同时发生在到期时点**，不存在「结算了但还能改结论」的中间窗口。
- 新手任务**不发放积分**（`points` 恒为 0），因此只参与冻结、不参与结算；它的截止时间按**每个人的 `due_date`** 判定，不是任务级日期。

## 2. 需求清单

### A. 统一的有效截止时间

| 编号 | 需求                                                                                                                              | 验收方式                       |
| ---- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| A1   | 每类任务都有一个**有效截止时间**：普通任务与悬赏用任务级 `end_date`；新手任务用**对象级 `due_date`**（= 本人分配日 + 大任务时长） | 三类任务的到期判定都能命中     |
| A2   | **到期**的两种情形：有效截止时间已过（`< 今天`），或任务被管理员结束为 `CLOSED`                                                   | 两种情形都触发冻结与结算       |
| A3   | 有效截止时间为空表示**永不到期**：普通任务与悬赏的 `end_date` 允许为空，此时只能靠管理员结束任务来触发                            | 空日期任务不会被自动结算       |
| A4   | 到期判定一律使用实验室时区 `Asia/Shanghai`                                                                                        | 跨日边界不偏移                 |
| A5   | 到期**不改变任何对象状态**：不自动打回、不自动作废、不自动置为失败，只作为校验与结算依据                                          | 到期后对象状态与到期前完全一致 |

### B. 到期冻结：成员侧

| 编号 | 需求                                                                                         | 验收方式                 |
| ---- | -------------------------------------------------------------------------------------------- | ------------------------ |
| B1   | 到期后成员**不能再提交或修改完成说明**（普通任务与新手的提交、悬赏的「提交即完成」全部禁止） | 到期后提交返回 409       |
| B2   | 到期后成员**不能再提交或修改子任务内容**                                                     | 到期后子任务提交返回 409 |
| B3   | 悬赏：到期后**不能再接取、不能再放弃**；成员侧整体只读                                       | 到期后接取/放弃返回 409  |
| B4   | 新手任务按**本人的 `due_date`** 冻结，与其他报名者互不影响                                   | 只有逾期的那个人被冻结   |
| B5   | 冻结判定实时读取截止时间：管理员延长后成员侧**立即恢复**可提交，不需要重置任何对象状态       | 延长后同一对象可继续提交 |

### C. 到期冻结：管理侧

| 编号 | 需求                                                                                                                                                                                           | 验收方式                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| C1   | 到期后**不能再审核通过**：普通任务的人工通过、新手任务的转正审核都拒绝                                                                                                                         | 到期后审核返回 409               |
| C2   | 到期后**不能再驳回**：普通任务、悬赏、新手任务一律禁止（这就是「结算后不能驳回」的落地口径）                                                                                                   | 到期后驳回返回 409               |
| C3   | 到期后**保留补救动作**：延长截止日期、以及悬赏的「移除接取者」（清理动作，不产生结论）                                                                                                         | 延长与移除仍可执行               |
| C3.1 | **补救只对「截止日期已过但任务仍为 `PUBLISHED`」有效**：`CLOSED`（管理员主动结束）是**不可逆终局**，延长截止日期解不开它，因此结束之前必须先完成审核；结束时同步结算，即「结束 = 结算 = 终局」 | `CLOSED` 任务延长后审核仍 409    |
| C4   | 到期时仍处于「已提交待审核」（`SUBMITTED`）的普通任务对象不自动变更；管理员仍可迟到审核，未通过对象不计分                                                                                      | 状态不自动变化；迟到通过计分一次 |
| C5   | 管理端提示待审核数量；到期后说明成员不能再提交，但已提交内容仍可审核并在驳回时获得 24 小时补交                                                                                                 | 列表与详情页可见当前提示         |
| C6   | 悬赏的奖金顺延只在**到期前**发生（因为驳回只在到期前可用）；到期后奖金持有者冻结                                                                                                               | 到期后无法再触发顺延             |

### D. 到期结算（积分）

| 编号 | 需求                                                                                                                                       | 验收方式                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| D1   | 到期后由**定时任务自动结算**，不依赖管理员点击；调度频率可配置，默认每小时检查一次                                                         | 到期后一个调度周期内完成结算     |
| D2   | **结算资格只看结算那一刻的对象状态**：只有 `APPROVED` 获得积分；`SUBMITTED`、`PENDING`、`REJECTED`、`ABANDONED` 一律不发                   | 五类状态逐一验证                 |
| D3   | 管理员**结束任务时同步触发一次结算**（与定时任务共用同一段幂等逻辑），不必等下一个调度周期                                                 | 结束即结算                       |
| D4   | **幂等 + 跨实例互斥**：任务级结算标记 `points_settled_at` 做条件更新认领；每人一笔的来源编号唯一，重复执行不重复计分                       | 连续结算两次积分记录不增加       |
| D5   | `points = 0` 的任务**不进入结算队列**（新手任务天然不参与；不绑积分的悬赏也不参与）                                                        | 无积分记录、无结算标记           |
| D6   | 积分发放的**操作人（operator）统一记为任务创建者**；普通任务由原来的「审核人」改为「创建者」，属公开的行为变化                             | 积分流水的操作人为任务创建者     |
| D7   | 三种情况**结算跳过并记录原因**：对象是教师 / 对象不是正式成员 / 对象就是任务创建者本人                                                     | 原因落库并在界面显示             |
| D8   | **延长截止日期时，若该任务已结算，则结算标记重置为未结算**，新完成者在再次到期后补发；已发过的靠来源编号幂等跳过（新手任务按人延长时同理） | 延长后重新进入待结算、只补发新增 |
| D9   | 结算**不撤回**任何积分；更正走现有「积分管理」的反向流水（与「到期即不能驳回」配套，结论一旦结算即为终局）                                 | 无自动反向流水                   |
| D10  | 结算**不新增任何对外接口**（没有「手动结算」入口）                                                                                         | 无结算端点                       |
| D11  | 结算**不给未完成者发催办消息**；只给获得积分者发积分到账消息（积分模块既有行为），并给任务创建者发一条结算汇总                             | 无催办消息                       |

### E. 新手任务专项

| 编号 | 需求                                                                                                                                                                    | 验收方式                         |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| E1   | 新手任务 `points` 恒为 0，**不参与积分结算**，只参与到期冻结                                                                                                            | 新手任务无积分记录               |
| E2   | 新手任务对象到期后，管理员**不能审核通过、不能驳回**；恢复操作必须先把该人的截止日期重新推到未来                                                                        | 逾期对象审核返回 409，延长后成功 |

| E4   | 保留既有的批量口径：调整大任务时长会按各自发放日重算所有未通过对象的 `due_date`（影响面在界面上明确提示）                                                               | 时长变更时全部未通过对象重算     |
| E5   | 保留「打回技能测试阶段」作为另一条出口：打回会按当前时长重置该人的 `due_date`                                                                                           | 打回后日期重置、可重新提交与审核 |
| E6   | 管理端对逾期对象显示「已逾期，无法审核；请先延长截止日期或打回技能测试阶段」，并就地给出两个动作入口                                                                    | 界面可用且不再出现死路           |

## 3. 三类任务的差异一览

|                | 新手任务 `ONBOARDING`                             | 普通任务 `STANDARD`                           | 悬赏任务 `BOUNTY`                      |
| -------------- | ------------------------------------------------- | --------------------------------------------- | -------------------------------------- |
| 有效截止时间   | **对象级 `due_date`**（每人不同）                 | 任务级 `end_date`（可空）                     | 任务级 `end_date`（可空）              |
| 到期后的成员侧 | 不能提交完成说明与子任务内容                      | 不能提交完成说明与子任务内容                  | 不能再接取、提交、放弃                 |
| 到期后的管理侧 | 不能审核转正、不能驳回；可**按人延长**或打回      | 不能审核通过、不能驳回；可延长截止日期        | 不能驳回；可延长截止日期、可移除接取者 |
| 是否结算积分   | **不结算**（`points` 恒为 0）                     | 结算（`APPROVED` 才发）                       | 结算（`APPROVED` 才发）                |
| 到期的历史口径 | 只显示「已逾期」，管理员仍可审核 → **被本次推翻** | 只显示「已逾期」，不阻止提交 → **被本次推翻** | 本次新增                               |

## 4. 明确不做

- 到期自动打回、自动作废、自动置为失败、自动延长
- 对未完成者的自动催办、截止前定时提醒
- 对外暴露的「手动结算」接口
- 结算后撤销结算标记（只有「延长截止日期」会重置标记）
- 分阶段结算（如按人分批发放）
- 修改已上线的 `V11`—`V13` 迁移脚本

## 5. 本次对已上线行为的变化（必须逐条确认）

| 变化                                               | 影响                                                                                        |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **普通任务积分从「审核通过即发」改为「到期结算」** | 成员在任务期间看不到积分到账，要等到期；结算只认 `APPROVED`，因此**到期前必须审核完**       |
| **普通任务截止只限制成员提交**                     | 到期后成员不能再提交；管理员仍可审核已提交对象                                              |
| **截止后审核通过**                                 | 普通任务通过后计分；若已结算则经相同幂等来源补发                                            |
| **积分流水的操作人从「审核人」变为「任务创建者」** | 历史流水不变，新流水显示创建者                                                              |
| **新手任务截止后仍可审核已提交对象**               | 不能提交新内容；管理员可通过转正或驳回，驳回后开启个人 24 小时补交窗口                      |
| **新手任务从「逾期只显示」改为「逾期冻结」**       | 与 `docs/task-module-design.md` 第 4.8 节「到期后不自动处理、只显示已逾期」冲突，需同步修订 |

6. 悬赏实测：结算后不能驳回；驳回只在到期前可用；奖金顺延只在到期前发生
