## 2. 折叠榜单与缓存

- `PointService` 保留统一排序/并列规则。公开投影在服务端限制每榜最多 6 行，增加 `totalCount`；公共首页、公开排名端点、开发 fallback 和序列化快照一并缩减，避免另一个端点仍返回完整名单。
- 成员完整列表复用现有积分接口及角色守卫，可加分页参数；展开区域保持总/月/年周期一致。UI 可提供“进入积分榜”链接，不把访客转成成员。
- 使用 `ResizeObserver` 观察外部可用高度与行高，按 `floor((budget - fixedParts) / rowHeight)` 计算预览行数，边界 1—6；空榜为 0。外部预算来自相邻成员卡或单栏高度上限，不测自身随行数变化的内容高度，避免循环布局。标题与按钮换行也重新扣除预算。
- 展开区采用有界滚动列表，成员名单较大时服务端分页；按钮 `aria-expanded` / `aria-controls`，加载和错误区域稳定，切换周期避免旧请求覆盖新周期。
- 首页缓存升级版本并清理旧版本的完整榜单快照；完整成员数据只放内存，退出登录立即清空并收起。每日刷新与跨日恢复前台沿用上一批实现。

## 3. 基金账本与权限

### 数据与事务

新增单账户 `fund_accounts` 和流水 `fund_entries`，金额均 `DECIMAL(19,2)` / `BigDecimal`，不使用浮点数。账户保存唯一键、币种、初始化时间、期初余额及当前余额；流水保存 UUID、OPENING/INCOME/EXPENSE/REVERSAL 类型、金额、发生日期、事项/说明、操作者、系统时间、原流水关联及撤销原因。

账户余额作为事务内更新的汇总，流水为可重算的依据。累计收入/支出只计未撤销对应流水，期初余额单列。初始化在同一事务创建 OPENING 流水并更新账户，唯一约束保证只初始化一次；初始化后不直接编辑期初数额，确需调整按实际收入/支出记录说明。

所有资金变动按账户行 `PESSIMISTIC_WRITE` 串行校验与更新，支出和撤销收入不得造成负余额。前端生成请求键，后端保存规范化请求摘要；同键同参数回放，同键不同参数拒绝。数据库唯一请求键及唯一撤销来源约束是最终防线，唯一冲突在事务外处理，不在已失败事务中继续查询。

撤销创建反向流水，保留原记录；不向用户提供删除或覆盖流水的接口。撤销收入/支出从有效收支合计剔除原记录，反向流水不计作一次新的日常收入/支出，避免总额虚增。

### API 与页面

| 接口/路径                                                   | 权限与内容                                                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `GET /api/v1/public/fund/summary`                           | 仅 initialized、币种、期初余额是否已登记、余额、累计收入/支出、汇总更新时间；不含流水和人员 |
| `GET /api/v1/fund`、`GET /api/v1/fund/entries`              | 成员角色；账户汇总及分页/筛选明细                                                           |
| `POST /api/v1/fund/initialize`、`POST /api/v1/fund/entries` | 新增 `FUND_MANAGE`，授予现有教师/核心学生角色                                               |
| `POST /api/v1/fund/entries/{id}/reverse`                    | `FUND_MANAGE`，原因与请求键必填，来源必须为未撤销收支                                       |
| `/fund`                                                     | 成员路由；汇总在上、筛选/流水在下，管理操作按权限显示；手机流水卡片化或限定表格横向滚动     |

权限由服务端当前账号角色/权限校验，不能仅依赖 JWT 中旧的客户端展示信息。公开主页摘要与明细分离加载；汇总失败显示失败提示，不沿用未知零余额。记账失败保留输入，成功刷新汇总和明细。基金不接入转账/在线支付。

## 4. 竞赛状态与报名文件

- 保留既有 `CompetitionLifecycle` 与数据库取值，新建记录只提供 PLANNED（未开始）和 FINISHED（完赛）。结果字段使用 VARCHAR 存储 `PENDING_RESULT / AWARDED / NO_AWARD`，避免修改历史数据库 ENUM。
- 页面把 FINISHED + PENDING_RESULT 展示为“完赛 · 待成绩”，FINISHED + AWARDED/NO_AWARD 展示为“完赛 · 已结束 · 获奖/未获奖”。PLANNED 不允许填写完赛结果。其他组合在服务端拒绝。
- 历史 ONGOING 保留“历史：进行中”只读标签，编辑时由操作者选择实际主状态；历史 FINISHED 有奖项/证书按兼容视图展示旧成果，缺乏信息的记录标记待补齐，不能批量猜测修改历史状态。
- 必填具体名称、统一比赛日期、报名截图；track/level/项目/参赛成员沿用现有可选或必要字段，省赛/国赛日期调整为可选并保留已有值。待成绩和未获奖无需证书，获奖成果仍校验奖项和证书。
- 报名截图使用独立存储目录与元数据（originalName、storedName、detectedContentType、size），允许真实 PNG/JPEG/WebP，校验真实内容、尺寸和现有图片上传大小边界；存储名由系统生成。认证下载设置私有缓存，不接入公开图片 URL。替换文件先成功保存并提交元数据，之后清理旧文件，失败回滚清理新文件。
- 新建采用 multipart 同时提交字段和报名截图；更新字段和替换报名截图的 API 保持一致校验。旧记录不因只读展示缺文件报错；下一次完整编辑时提示补齐必要登记信息。
- 已结束获奖进入现有审核，改名/日期/奖项/证书等关键内容重新待审核。参赛登记及未获奖归档不自动成为公开成果，也不自动生成积分。
- 在 `PointService` 来源列表与发放守卫增加结果状态门槛，公开获奖成果查询使用同一判定；历史已审核获奖记录保持兼容可用。之前的来源关联、关联成员和请求幂等保持有效。
- 用户已确认队长统一登记，继续复用现有 CompetitionEntity 及参赛成员关联，不新增个人报名表。队长自动为提交人并加入关联名单；个人赛就是仅有本人的记录。团队报名图一份即可，编辑仍按既有队长/管理员权限，成员关联通过真实 profile ID 同步到个人倒计时。

## 5. 倒计时聚合与数据边界

新增 deadline 模块，提供 `GET /api/v1/public/deadlines` 与成员 `GET /api/v1/me/deadlines`。按类型筛选与分页，稳定排序按期限、类型、来源 UUID；响应包含服务器北京时间基准、sourceType、sourceId、milestoneKey、title、deadlineDate 或 deadlineAt、状态与可访问入口，不含附件/个人分配列表。

公开范围和个人范围在服务端分开查询与投影；新手任务的全局最近日期用数据库聚合，不把逐人分配序列化后交由前端裁剪。公开项目不受原首页展示开关限制，公开字段按已审核第 9 节增加参加成员姓名/角色；原项目详情的权限和公开正文接口不因此改变。

普通任务/悬赏取已发布任务级日期，每个任务去重；本人普通/新手任务取个人有效截止，新手延期沿用 `TaskTiming.deadlineOf`，被驳回对象优先有效重交 `Instant`。已完成对象和放弃悬赏排除，不改后台结算或冻结条件。首页新手聚合无有效截止时不生成虚假倒计时。

比赛取未开始记录的统一比赛日期及有效后续赛段，历史 ONGOING 同样保留有日期的后续赛段，按 sourceId + milestoneKey 去重；已完赛待成绩不生成没有发布日期的出分倒计时。项目取 PLANNING/ACTIVE 的 endDate；不含 PAUSED/COMPLETED/ARCHIVED。个人关联采用负责人/队长/指导老师/成员真实 ID，不根据管理员角色或姓名推断参与。

前端 `DeadlinePanel` 支持首页全局和个人两种模式，共享类型标签、时间文案、逾期区、紧凑预览和分页。日期级数据跨日更新；精确重交倒计时可用每分钟文本更新，到达时间边界立即更新状态。载入时、恢复前台跨日/越过精确期限、来源操作成功时重取数据；清理定时器与监听，不引入秒级网络轮询。

该聚合接口不能承诺未知赛事/未设置期限；仅覆盖系统已登记数据。任何详情链接仍接受源模块鉴权，访客点击受保护详情获得登录提示。

### 循环与静态切换

- 新增 HomepageDeadlineConveyor，首页保留基金与日程双栏、手机堆叠布局。卡片宽度随栏宽适配；1–2 条静态网格，手机纵向展示。ResizeObserver 测量容器和原始队列，只有至少 3 条且原始队列宽度超过容器时启动自动滚动。
- 横向原生滚动容器使用 requestAnimationFrame 按时间增量匀速移动，初始约 24px/s。按视口需求补齐复制卡片，跨过原始队列宽度时回绕；复制项 aria-hidden/inert，不产生重复焦点。恢复时重置时间基准，避免跳动。
- 停在循环接缝时，将原始队列的展示起点旋转到当前可见位置，并保留卡片内像素偏移；让可见复制卡片转为真实可操作卡片，不增加重复焦点或不可点击的成员入口。转静态或切换数据队列时恢复服务端顺序。
- 暂停条件统一组合：手动暂停、悬停、focus-within、触摸/拖动、成员详情展开、文档隐藏、离开视口或减少动态。只有全部解除才自动恢复，按键和原生滑动仍可浏览；取消滚动模式时移除副本并复位。
- 成员默认显示 3 位与总数，展开完整名单采用有界区域并暂停播放；同名不同身份不合并，负责人/队长兼成员仅出现一次并保留角色。卡片名称换行，关键类型、日期和倒计时始终可读。
- 提供 44px 暂停/继续、前后按钮和可见焦点。连续倒计时不使用 aria-live 播报；卸载清理帧、观察器、事件和计时器。
