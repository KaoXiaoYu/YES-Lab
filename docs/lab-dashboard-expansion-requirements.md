## 1. 已确认范围

- 首页积分榜默认只显示栏位能容纳的前几名，可展开完整榜单；完整榜单只对成员开放。保留总榜、月榜、年榜与每日刷新，取消方向榜的既有决定继续有效。
- 新增一个人民币实验室基金账户。教师与核心学生记账，成员查看明细；主页公开余额、累计收入、累计支出。
- 每个人登记参赛情况，包括未获奖比赛，填写具体名称、报名截图、比赛时间。两个主状态为“未开始”和“完赛”；完赛分“待成绩”和“已结束”，已结束明确获奖或未获奖。
- 首页展示全实验室任务、悬赏、比赛、项目的倒计时；个人操作台展示本人接取或参与的事项。访客也能看到全部事项名称和时间，详情沿用各模块现有权限。
- 用户已确认团队参赛由队长统一提交一条记录和报名截图，关联成员即可；不要求队员重复提交同一场团队比赛。

本轮“成员权限”沿用教师、核心学生、成员三类账号；访客账号即使已登录也不获得明细权限。个人操作台使用现有 `/profile` 个人主页，不额外建设一个重复的个人首页。

## 4. 参赛登记与成绩状态

| 编号 | 要求                                                                                 | 验收                                                                |
| ---- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| C1   | 成员可登记所有参赛记录，包括没有获奖；具体比赛名称、比赛日期和报名截图为新记录必填项 | 缺项不能保存；不强制每场比赛同时有省赛和国赛时间                    |

| C7   | 成果审核、首页获奖展示及竞赛积分仅面向“已结束、获奖、审核通过”的记录                 | 未获奖、待成绩、未开始不能进入获奖积分来源；不自动发分              |
| C8   | 历史状态与文件可读，缺报名截图的历史记录标为未补齐，不批量猜测补齐                   | 不改已应用迁移，不强行将历史“进行中”误写为完赛                      |

团队参赛方式：**队长提交一条团队记录和报名截图，关联成员即可**。个人赛由本人提交，作为单人记录。保留库内关联项目及成员的能力，不按姓名猜测绑定账号；团队关联成员均可在个人倒计时看到该场比赛，编辑仍按现有队长/管理员权限。历史获奖证书继续保留；此前删除的是积分管理中的凭证输入，并不删除竞赛证书。

未开始与待成绩记录属于参赛登记，暂不要求走获奖成果审核；更新为已结束获奖后进入现有成果审核，后续修改成果关键字段仍使审核失效。已结束未获奖仅归档参赛记录，不作为获奖成果公开展示。

## 5. 统一倒计时

| -------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 普通任务 | 已发布、有截止日期的任务，每个任务一条                                                 | 本人已有任务分配，采用其有效截止时间；驳回重交显示精确重交期限 |
| 悬赏任务 | 已发布、有截止日期的悬赏，每个任务一条                                                 | 本人已接取且未放弃的悬赏                                       |
| 新手任务 | 共享大任务展示“最近一批截止”，按尚未完成对象的有效日期汇总，不公开成员名单             | 本人任务的有效截止，包括个人延期和重交期限                     |
| 比赛     | 已提交的未开始比赛及其有日期的后续赛段，名称和日期公开；历史进行中记录保留有效后续赛段 | 本人作为队长、指导老师或关联成员参与的比赛                     |
| 项目     | 规划中、进行中且有结束日期的项目；包括未开启公开展示的项目名称与日期                   | 本人是负责人、指导老师或关联成员的项目；管理权限本身不视为参与 |

- 展示类型、事项名称、期限、剩余时间与状态，最近期限优先；初始列表有界，提供按类型筛选和展开/分页，不用无限长列表替代旧榜单问题。
- 普通日期按北京时间自然日显示“剩余 N 天 / 今天截止 / 已逾期 N 天”；当天仍可办理，和现有任务规则一致。精确重交期限按剩余小时/分钟显示，到期明确提示，且不能改变实际业务冻结规则。
- 完成的个人任务、已关闭任务、已结束比赛、已完成/归档项目不进入进行中的倒计时；逾期但尚未处理的有效记录单列“已逾期”。暂停项目不进行倒计时，恢复后重新显示。
- 无日期事项不编造期限，不进入倒计时，源详情中保持“不限/未设置”说明。草稿任务不因公开倒计时而暴露；新手任务个人隐私与个人重交时间不在首页公开。
- “全部”指以上进行中的库内事项，不截断数据源；首页按第 7 节完整加载并展示。公开字段按第 7 节增加参加成员姓名/角色，仍不扩大项目内容、任务提交、报名截图、联系方式或内部编号的读取权限。
- 首页卡片名为“实验室倒计时”，个人主页卡片名为“我的倒计时”。撤掉原全站单场比赛悬浮卡，避免覆盖手机内容和重复展示。

- 后端覆盖金额精度、余额并发、重试/撤销审计、比赛状态组合/上传隔离、积分来源门槛、日期边界、个人关联与任务延期/重交一致性。

- 新迁移先备份数据库、上传文件及 Flyway 历史，在预生产 MySQL 8.4 演练现有库和空库，核对历史状态/证书、期初余额、索引与幂等约束；H2 不替代该验收。

## 7. 首页倒计时传送带补充（2026-10-04，已审核）

用户要求首页像旋转寿司一样循环播放全部倒计时，显示类型、名称及参加成员；倒计时太少时不滚动。用户于 2026-10-04 回复“是的”审核通过。本节覆盖第 5 节首页展示方式，个人操作台仍使用原有列表。

- 首页横向连续播放全部有效日程，可按类型筛选；不能只循环接口第一页。延续既定有效范围、逾期分区、比赛赛段和日期计算规则。
- 只有 1–2 条时静态显示；即使有 3 条以上，只要当前栏宽能完整容纳，也不滚动。内容至少 3 条且放不下时才自动循环，窗口变化后重新判断。
- 卡片显示任务/悬赏任务/新手任务/项目/比赛类型、名称、节点、截止时间、剩余时间及参加成员。普通任务取真实分配成员，悬赏取有效接取成员，项目取团队成员及负责人/导师，比赛取关联参赛成员及队长/导师。角色重复合并，同名不同成员保留；历史手填参赛姓名仅作展示。
- 默认显示前 3 位参加成员和总人数，展开可查看全部姓名及角色；没有成员时显示待分配或暂无人接取。公开仅姓名与角色，不增加联系方式、内部编号、参赛附件或提交内容。
- 共享新手任务涉及招新申请者，沿用原公开保护范围，仅显示参与人数，不公开申请者姓名；这是已审核的成员展示例外。
- 提供暂停/继续与前后切换。悬停、键盘聚焦、触摸操作、成员展开、页面隐藏或板块离开视口时暂停；手动暂停不会被这些临时暂停的结束覆盖。
- 减少动态偏好下静态显示并支持手动查看全部；少量卡片在手机上纵向完整展示。复制卡片不重复进入键盘或屏幕阅读器顺序。
- 验收覆盖少量静态、全部容纳、溢出循环、全部分页数据、完整成员、暂停组合、键盘和减少动态，以及 375/768/1024/1440 明暗截图。本次无数据库迁移。

用户要求两个内容放到开屏下方，倒计时横向占满页面，基金只需一小块；全部列表内容循环播放，逾期超过 14 天不进入播放列表。已提供三个排布方案，用户选择第二种“基金摘要条”并批准施工，本节覆盖第 7 节冲突部分。

- 基金摘要条：首屏下先一条约 72–88px 的基金摘要，余额为主、累计收入/支出为辅，右侧成员明细入口；下方独立全宽倒计时。视觉清晰、基金低高度、倒计时桌面可见约 4 张完整卡片。
