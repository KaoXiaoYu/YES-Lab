# 积分管理联动与首页同步需求清单

> 2026-10-03。用户已确认：项目/竞赛积分只发给对应关联成员；首页先只保留总榜、月榜、年榜。用户已审核本文与技术设计，并将自动刷新调整为每日；发生冲突时以本文为准。

## 1. 问题与范围

- 公开首页榜单读取演示分数，未使用真实积分账本；前端还按成员下标配分，成员列表变动会造成身份与分数错配。
- 管理员手填竞赛/项目事项，未与库内记录关联；来源编号、凭证地址都是必填项。
- 本轮调整首页榜单及管理员积分发放、撤销与流水展示。任务到期结算、既有积分分配方式、月度封顶与权限沿用现行规则。

## 2. 需求清单

| 编号 | 要求                                                                                                         | 验收结果                                           |
| ---- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| P1   | 首页总榜、月榜、年榜接入真实成员积分，使用成员 ID 配对身份；排序、并列名次与站内排行榜一致                   | 发放/撤销后分数和成员正确对应                      |
| P2   | 月榜、年榜按北京时间的自然周期与积分发生日期统计；总榜使用现行成员总分，保留历史余额                         | 跨月、跨年、撤销与零分结果正确                     |
| P3   | 首页按北京时间每天零点自动刷新；页面跨日后重新可见时补刷新。加载、空态、失败均有反馈，失败不得回退成演示分数 | 首页下一次每日刷新或重新打开页面时显示已提交的变动 |
| P4   | 首页只保留总榜、月榜、年榜，暂时去掉没有真实计分规则的三个方向榜                                             | 不再展示方向榜演示分数                             |
| P5   | 竞赛获奖必须选择竞赛库已有记录；只允许已结束、审核通过且已登记奖项的成果                                     | 缺少关联、非法记录、未满足成果状态均不能发放       |
| P6   | 项目任务必须选择项目库已有项目，关联不以项目是否在公开首页展示为条件                                         | 私有项目仍可按管理员权限选择；不存在的项目拒绝     |
| P7   | 项目/竞赛发放对象仅为对应的项目成员/参赛关联成员；同时满足正式学生、非教师、非操作人等现有资格               | 前端限制候选，服务端拒绝伪造的非关联成员           |
| P8   | 队长/项目负责人若为正式学生，计入候选；竞赛中只有显示姓名、未绑定本站成员的参赛者不能发分                    | 不按姓名猜测或自动绑定账号                         |
| P9   | 积分编号由后端生成，含北京时间日期时间和唯一后缀，流水只读展示为“积分编号”                                   | 无编号输入；并发发放编号不重复                     |
| P10  | 去掉新增凭证地址、撤销时的新凭证地址、流水查看凭证入口及相关必填校验；保留事项说明                           | 无凭证也能新增/撤销；历史凭证数据保留但不展示      |
| P11  | 保留事项名称、日期、分值、事项说明及成员贡献/分配；切换来源清空旧成员选择                                    | 来源不同不会误给上一批成员发放                     |
| P12  | 请求重试不得重复发分；撤销仍创建反向流水，撤销原因必填；业务上允许同一项目有多个积分事项                     | 同一请求只生成一批；不同事项可分别登记             |
| P13  | 保存关联来源及名称快照；历史未关联积分可读、可撤销，不按标题自动补绑，不重写历史编号                         | 来源编辑或删除后仍可追溯当时事项                   |
| P14  | 实验室贡献、宣传等其他积分类型仍按原资格选择成员，不强制关联项目/竞赛                                        | 现有非项目/竞赛发放流程回归通过                    |

## 3. 界面安排

表单顺序为“积分类型 → 选择竞赛/项目（按类型出现）→ 事项名称、发生日期、分值 → 事项说明 → 关联成员与贡献分配 → 确认发放”。选中来源后回填建议事项名称，允许补充具体工作说明；来源名称在流水中独立展示。

编号在保存成功及流水中显示，不提供可编辑输入。撤销表单只填写撤销原因。其他积分类型沿用原成员候选方式。

沿用 `design-system/openlims/MASTER.md` 与首页覆盖规则，错误就地显示并聚焦错误摘要，失败保留输入；加载来源时稳定布局并禁用依赖操作。手机与桌面、亮暗模式均需截图验收。

## 4. 不包含与审核项

- 不增加审核通过自动发分、竞赛固定分值表或项目状态触发器；管理员仍选择事项并确认发放。
- 不修改任务结算时点、系统任务来源幂等编号、成员月度上限、管理员自发分限制或竞赛库原有证书功能。
- 不定义方向榜计分规则，不迁移或推测绑定历史流水。
- 审核结论：用户已批准其余方案，P5 竞赛成果状态门槛已确认。

## 5. 验收与上线

- 后端：来源存在与类型匹配、关联成员及资格校验、整批回滚、请求重试/并发、编号唯一、反向流水、封顶、任务结算回归。
- 首页：未登录可读取真实总/月/年榜；身份映射、同分名次、周期边界、每日刷新、空库与网络失败；公开响应不包含账号、内部编号或联系方式。
- 前端：完整检查与生产构建；真实本地后端和 Chrome CDP 截图，1440/375 × 亮暗，另查 768/1024 布局、44px 交互区域、可见焦点、4.5:1 对比度与减少动态。
- 新迁移上线前备份数据库及迁移历史，预生产 MySQL 分别演练已有库/空库、重复执行相关补缺逻辑；核对历史行、索引、关联及请求唯一约束。H2 测试不能替代迁移和 InnoDB 并发验收。
- 部署后以一笔库内竞赛积分和一笔项目积分验收首页同步、受限成员与撤销；避免给同一事项重复新增。临时服务和数据库实例必须在收尾关停并记录。
