# 导航整合与模块化报名表需求清单

日期：2026-10-15。状态：用户于 2026-10-15 批准实施；第一批已完成；报名表后续三批待施工。对应设计：`docs/navigation-recruitment-design-20261015.md`；对比依据：`docs/openlims-diff-20261015.md`。

## 1. 范围与保留原则

实现用户最初列出的导航、个人主页、任务管理与模块化报名表需求。用户随后说明成果来自 OpenLIMS，并要求先为 YES Lab 设计：因此 YES Lab 的前面三项仍需后续增量施工，不能记作本地已完成。

“已有内容不进行改变”落实为：保留 YES Lab 品牌、首页内容/配置、现有业务能力、权限枚举、历史数据及旧路由；只调整需求明确要求的入口、页面组织及新增表单能力。不扩大到公开首页改版、测验、写题、问卷分析、导出、条件分支、多套表单或自动评分。

## 2. 导航、个人主页及任务管理

- 成员顶栏移除“公开首页”；Logo 仍指向 `/`。“后台管理”直接进入 `/admin`。
- 导航按实际容器与项目宽度分配；全部可显示时不出现“更多”，否则只收纳放不下的项目。保留角色可见性、账号操作、键盘焦点和菜单关闭行为。
- 本人统一入口“个人主页”，合入今日待办，避免同一页面重复展示日程/积分或重复请求；保留资料、任务、悬赏推荐与密码等现有能力。`/today` 兼容进入 `/profile`。
- 公开成员详情展示每日积分热力图；只公开总积分、每日汇总、服务端日期，不公开流水、原因、任务标识、私人待办或其他私人资料。
- `/admin/tasks` 共用一个标题与页面框架，普通、新手、悬赏三个同级分类；新手内容直接显示，删除独立标题与“返回任务管理”。后台侧栏不再单列悬赏管理，成员悬赏榜保留。
- 旧新手/悬赏管理链接定位对应分类；任务进度、子任务、悬赏名单/履约详情地址保留。切换分类、页面与浏览器返回时保留必要的未保存提醒。

## 3. 全局报名表

全局仅一份可编辑草稿和一个当前发布版本，管理操作沿用 `RECRUITMENT_MANAGE`；不新增权限或改变角色分配。支持添加、编辑、删除、启停与排序普通模块；基础信息恰好一个，技术认知最多一个。

| 类型     | 能力与约束                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------ |
| 基础信息 | 姓名、邮箱、专业、班级保持必填且启用，不能删除或改变系统含义；其余现有资料保留。可调整标题、说明与顺序 |
| 选择题   | 单选/多选；管理者自定义选项、顺序、必填、最少/最多选择数；可添加多个独立问题                           |
| 自由填写 | 单行/多行；必要的长度、邮箱、电话、URL 校验；保留现有标签列表与个人链接能力                            |
| 内容上传 | JPG/PNG/WebP、PDF；多模块分别收集；显示数量、大小、类型限制和上传结果                                  |
| 技术认知 | 独立启停，启用时分配 5 题且至少回答 3 题；不改变既有题库和分配规则                                     |
| 说明     | 纯文字分组标题、填写指引，不收集答案、不参与必填检查                                                   |

首个发布版本包含本地现有全部填写能力，不替换既有兴趣方向与题库。基础模块不可删除/停用；技术模块以启停为主要操作；普通模块可重复添加并使用独立 ID。

## 4. 草稿、发布和历史报名

- 编辑器提供“保存草稿、预览、发布”三个明确操作；保存不影响报名者；发布记录操作者和时间。
- 草稿并发冲突必须提示并保留本地输入；不得覆盖他人的新修改。发布前保存并校验，确认本次将发布的内容。
- 首次成功提交绑定当时的不可变发布版本；初筛前修改仍使用原版本；以后发布不改变历史题目、顺序、选项、答案或文件。
- 未提交者遇到新版，提示更新并保留可匹配输入供复核；不自动删除不匹配答案。旧报名继续原字段/题目/图片展示，不强制迁移。
- 进入初筛后禁止本人修改报名正文、增删附件；面试、技能测试、转正和现有资料补全规则继续沿用。

## 5. 建议采用的上限（随设计审核）

采用 OpenLIMS 已建模上限并由服务端执行：最多 50 模块，每个选择模块最多 30 选项，配置最多 256KiB；每个上传模块最多 6 份，图片每份 5MiB、PDF 每份 10MiB，全表最多 20 份/50MiB。管理者可设更低上限，不能提高至系统上限之外。页面显示常用 MB 文案，说明实际按 1024 进制计量。

上传只能由申请者本人及有招新管理权限者读取。校验真实类型、归属、阶段、各模块及全表限额；不公开静态下载 URL。不移动、删除或重写既有作品文件。

## 6. 三端交付与验收

后台编辑器、申请者填写页、管理员审核页必须共同接入，配置 API 本身不算完整交付。预览/填写/只读审核共用渲染与顺序规则，旧报名仍走 legacy 展示。

验收包括：多模块排序与答案归属、启停、预览与发布、版本竞争、旧报名、阶段限制、越权拒绝、文件失败重试、重复提交及并发覆盖。后台相关操作失败不得丢失输入。

界面遵循现有 `design-system/yes-lab/MASTER.md` 与任务页面覆盖，正文对比度 ≥4.5:1、44px 触控、可见焦点、减少动态；真实 Chrome 验收 375/768/1024/1440 明暗主题，截图归档。后续施工执行相关后端回归、完整 `npm run check` 与真实 MySQL 演练；推送后核对同一 SHA 的测试和 Web/API 镜像发布。
