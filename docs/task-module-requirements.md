# 任务模块 · 需求清单

> 本文为已审核并实施的任务模块需求清单。
> 详细技术设计见 `docs/task-module-design.md`。
> 基础模块已上线；2026-09-26 批准的资料自填与截止规则变更见第 8 节。
> 2026-10-02 普通任务按人补发方案见第 9 节，2026-10-02 已批准并实施。

## 1. 目标与范围

本次施工包含四件事：

1. **招新流程改造**：删除试用期阶段，技能测试通过后直接转为正式成员。
2. **新手任务**：作为技能测试阶段的转正门槛；全实验室一个共享大任务，管理员在其中维护子任务，子任务全部完成后审核转正。
3. **普通任务**：面向不同等级成员发放任务，支持富文本、子任务、起止日期、人工审核与自动计分。
4. **成员状态精简**：停用三个多余状态。

不在本次范围内的内容见第 4 节。

### B. 新手任务（共享大任务）

> 模型口径：新手任务是**全实验室唯一的一个大任务**，所有处于技能测试阶段的报名者**共享**它；
> 管理员在这个大任务里添加子任务，子任务从属于大任务；报名者只看到并勾选属于自己的进度；
> **每个子任务都要提交一段富文本内容**（不是勾选），全部子任务都提交后才能提交大任务，管理员审核通过即转正。不再有「模板复制给每人」这套机制。

| 编号  | 需求                                                                                                                                 | 验收方式                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------ |
| B1    | 新手任务是 `tasks` 中唯一一条 `ONBOARDING` 大任务，所有技能测试阶段报名者共享同一条任务（同一个 `taskId`）                           | 两位报名者拿到相同 taskId            |
| B2    | 三种面试通过入口（场次内提交通过、候补改判通过、场次结束后补录通过）都触发：在共享大任务上为该报名者建立一条对象，进度按人独立记录   | 三个入口均生成对象，互不影响         |
| B3    | 大任务内容由管理员在「任务管理 → 新手任务」直接维护：标题、富文本说明、**子任务清单（逐条添加/删除/排序）**、时长天数                | 页面可维护，保存即生效               |
| B4    | 时长默认 7 天，管理员可改（1—365）；每人的截止日期 = **本人被分配到大任务当天 + 时长**                                               | 同一大任务下各人截止日期按各自发放日 |
| B5    | 大任务不存在时用**代码内置默认内容**自动初始化，不阻塞招新                                                                           | 无数据时仍能分配                     |
| B6    | 同一报名记录在同一大任务上只会有一条对象（唯一约束），重复推进阶段不重复分配                                                         | 幂等                                 |
| B7    | 子任务的增删排序**保存后即时对所有在途对象生效**，不再有「模板」与「同步在途开关」                                                   | 改完立即在报名者页可见               |
| B8    | **新增**子任务时，已提交待确认的对象自动退回「待完成」并发送站内消息，需勾选新项后重新提交；**删除**子任务时同时删除对应勾选记录     | 状态与勾选记录正确                   |
| B9    | 修改时长后，尚未通过的对象按各自发放日期 + 新时长重算截止日期并发消息通知                                                            | 截止日期更新且本人收到消息           |
| B10   | 新手任务**不发放积分**（固定 0），只作转正门槛                                                                                       | 审核通过不产生积分记录               |
| B11   | 报名者在「我的报名」页看到大任务说明与**自己的进度**（已完成 x / y 项 + 进度条），可勾选子任务、提交完成说明、查看驳回意见与剩余天数 | 界面可用且进度准确                   |
| B12   | 子任务 = **标题 + 可选富文本正文（子任务说明）**，单层；**不设置截止日期**、不单独指派负责人、不单独计分、**不单独审核**             | 子任务无日期字段、无独立审核入口     |
| B13   | **全部子任务都已提交内容**后才能提交完成说明；管理员审核通过 → 直接转正；驳回 → 必填意见，补勾后可重新提交                           | 未勾完提交/审核被拒                  |
| B13.1 | 管理员只能驳回已提交待确认的新手任务；未提交对象不能被驳回并启动 24 小时补交窗口；未提交对象如确认免修，只能走必填理由的豁免转正     | 接口状态校验与管理端提示一致         |
| B14   | 到期不自动处理，只显示「已逾期」，由管理员手动调整时长或打回                                                                         | 无定时任务、无自动状态变更           |
| B16   | 报名者可从大任务进入**子任务页面**：看到该子任务的富文本正文与自己的完成状态，在此勾选完成，并可返回大任务（含总进度与截止日期）     | 子任务可深链、可勾选                 |
| B17   | 子任务正文允许为空（纯清单项）；非空时按 OWASP 白名单清洗，规则与任务正文一致                                                        | 空正文可保存；脚本被清洗             |
| B15   | 提供**批量补发**：为技能测试阶段且在该大任务上还没有对象的记录统一补建，幂等                                                         | 连续调用两次第二次为 0 条            |

## 4. 明确不做

- 自动判断任务是否完成、自动勾选子任务
- 截止前定时提醒、到期自动打回、逾期自动处理、自动催办
- 子任务嵌套、子任务独立指派负责人、子任务截止日期、子任务单独计分
- **子任务单独提交与单独审核**（子任务只做「看正文 + 勾选完成」，审核仍在大任务层做一次）
- 按对象设置不同积分值
- 新手任务发放积分
- 「撤销审核」及自动反向积分（更正走现有积分管理的反向流水）
- 新手任务大任务多版本管理与灰度
- 停用成员状态里的「试用」
- 合并教师与核心学生两个角色
- 任务附件上传、任务评论/讨论区、任务与项目或竞赛关联
- 任务模板、周期任务、批量导入

## 5. 待你确认的两项

1. **五个占位权限是否删除**：`QUIZ_MANAGE`、`QUIZ_PARTICIPATE`、`QUESTION_WRITE`、`TAG_MANAGE`、`SYSTEM_ADMIN` 目前没有任何接口引用，但 `AGENTS.md` 与 `DEVLOG.md` 明确记载「测验、写题及其管理业务仍只保留权限/字段，不实现业务功能」。**默认按「保留」施工**；若要删除请说明。
2. **存量状态的可见性**：成员状态下拉只剩试用与正式，但历史处于候选/暂停/退出的成员，其详情页仍会显示原状态文字。**默认保留显示**；若希望统一改写为某一状态请说明。

## 8. 招新资料自填与截止规则（2026-09-26 已批准，后续修订）
