# 开源适配需求与技术设计

> 2026-10-07 合并口径：本文保留远端开源适配的方案和历史验收边界；当前 YES Lab 实例保留原名称、主页内容、Logo、视觉样式、YESLAB 环境变量与部署路径。四套外观预设和新增仓库页脚仅保留为参考，未应用到当前界面。当前运行与部署以 README、docs/production-deployment.md 和 DEVLOG.md 最新记录为准。

本轮依据用户 2026-10-04 的明确要求实施；范围为品牌、可配置外观、开源文档与部署基线，不新增业务模块或改变业务流程。

## 核实与范围

- 以 `src/router/index.js`、各 Vue 页面、后端 Controller/Service、Role/Permission、生产配置及部署脚本为依据。保留公开首页与主页编辑、成员与账号、招新面试、个人主页、项目、比赛/成果/新闻、讨论、通知、三类任务、奖金履约、积分、基金、全局与个人日程。
- 使用原项目页面/API；不采用样品管理静态预览。测验、写题、项目即时聊天、竞赛批量导入仍未实现，不扩展预留权限。
- 用户确认仓库为 `https://github.com/KaoXiaoYu/YES-Lab`，选择 MIT。组织名仅用于真实仓库/镜像路径，不作为界面品牌；历史迁移内部变量名按兼容性约束保留。
- 初始副本没有 `.git`，适配期间冻结迁移。上传前取回官方历史，恢复仅变量更名的 V20，全部迁移与远端基线一致；生产 `flyway_schema_history` 尚未核对，不能承诺直接升级既有库，更不能执行 repair 掩盖差异。

## 技术方案

1. `config/branding.json` 为名称、Logo、favicon、分享图、描述及仓库地址的源码唯一配置。前端、HTML 元数据及 Java 默认内容共同读取；品牌身份优先于历史 CMS 名称，其他首页内容继续可编辑，不覆盖已有数据库内容。
2. `config/appearance.json` 定义通用、学术、工程、生命科学四套外观及默认项；`VITE_UI_PRESET` 可在构建时选择。四套共享原有页面、路由、权限与 API，支持明暗模式、自定义语义色、字体与圆角，不提供静态假业务。
3. 默认首页文案改为一般科研协作，保留 3D 模型上传/轮播以及已有栏目。默认示例身份去除原实验室人员指代；真实数据库记录不迁移、不批量改写。
4. 发布镜像命名空间从 GitHub 仓库自动导出；脚本支持指定 Fork 镜像命名空间，生产 Compose 无需源码中手改用户名。移除与独立部署无关的 Sites 构建绑定。
5. 重写 README、使用指南、部署手册与后端边界/权限说明；清理过时视觉指示，历史业务设计和迁移约束保留。既有历史文档须标注现行文档入口。

## 验收

- 前端完整 lint/format/build，后端 Java 21 全量测试与打包；迁移前后 SHA-256 相同。
- 本地 Vite + 8080 隔离 H2 + 真实 Chrome CDP，四外观桌面/手机明暗截图，默认外观 375/768/1024/1440；公开首页、登录、成员管理及其他模块入口/权限冒烟，检查溢出、图片、运行时错误、焦点、减少动态及对比度。
- 部署脚本语法/安全停止路径、生产配置解析、构建产物与共享配置打包可本机验证。没有可用 Docker 服务、Ubuntu/公网 DNS 或 MySQL 8.4 时，镜像实构、HTTPS、生产初始化、完整迁移/并发及备份恢复单独列为未验证，不把 H2 测试当作替代。
- 临时服务收尾关停；不连接生产、不改历史迁移、不提交或推送未授权的改动。
