# 按账号设置站内吉祥物

## 已确认需求

- 依据本次用户指令：增加替换入口，只有指导老师可以修改；针对部分账号设置，梅琳娜与奶龙可同时服务不同账号。
- 在成员管理的既有展示设置里，每个启用账号可选择梅琳娜或奶龙，默认梅琳娜；保留角色展示范围和账号显示/隐藏覆盖。
- 消息弹窗、消息面板、站内信箱的角色名与角色提示语同步切换。奶龙使用独立文案；业务通知正文保留其审核/流程含义。

## 技术设计

- 扩展原 `GET/PUT /api/v1/admin/notifications/melina-visibility`，仍由服务层 `hasRole('TEACHER')` 鉴权。核心成员、普通成员、访客均不能读取管理设置或修改。
- GET 的账号项增加 `mascot`（`MELINA` / `NAILONG`）；PUT 增加可选 `mascotOverrides: [{accountId, mascot}]`。传入时为所有启用账号的完整角色选择，未列出的启用账号恢复梅琳娜；省略/null 时兼容旧客户端并保留已有角色配置。禁用账号记录不随此次保存删除。
- 角色配置和可见性在同一事务内保存；拒绝重复、未知/停用账号与非法枚举。独立表以账号 UUID 为主键，默认形象无需记录；不修改既有可见性迁移或业务数据。
- 本人 `GET /api/v1/notifications/visibility` 和信箱响应增加 `mascot`。账号由 JWT 确认，不接受查询其他人的角色参数。发送者显示名按收件人的当前配置生成，不改历史通知记录。
- 前端复用原管理入口，账号行展示两个带标签的选择框；保存失败保留输入，保存时禁用编辑。消息中心每 15 秒/回到前台同步本人配置，隐藏账号也同步设置；本页保存通过事件刷新。
- `NotificationMascot.vue` 按配置渲染原梅琳娜组件或已制作的奶龙 SVG；角色文案集中维护。原显示权限优先于形象选择，选奶龙不会解锁被隐藏的消息入口。

## V19 人工迁移验收

1. 备份生产数据库和 `flyway_schema_history`；先在 MySQL 8.4 预生产库演练新增 `V19__notification_mascot_preferences.sql`，确认既有 V1—V18 校验和不变。
2. 检查新表账号主键、外键与角色枚举；重复执行建表语句不应报错，现有账号无记录时显示梅琳娜。自动化 H2 测试关闭 Flyway，不能代替本步骤。
3. 教师将账号 A 设奶龙、B 保留梅琳娜；分别登录确认图片、发送者和角色文案，再切回梅琳娜。退出登录/更换浏览器后配置仍保持。
4. 核心成员、成员、访客直接 PUT 必须 403，未登录请求必须 401；未知账号/重复账号/非法角色返回 400，整次保存不产生部分更新。
5. 核对原角色可见性、账号覆盖和历史通知数量未变化，隐藏账号的形象配置不能绕过隐藏。部署后核对 Flyway V19 成功和后台健康检查。
6. 回退旧前端时保留新增表；旧请求不带角色配置不得清空选择。禁止修改已应用迁移，禁止删除业务数据卷。
