# OpenLIMS 使用指南

以当前路由、服务端角色与领域校验为准。所有入口均为实际业务页面；需要登录的深链接会先进入登录页，再按身份跳转。页面隐藏按钮不构成权限保障，服务端仍验证每次操作。

## 角色与首次使用

- 匿名访客：公开首页、公开成员/已审核成果、公开项目展示与讨论只读；可以看到基金汇总和公开日程名称/时间。
- 游客 `VISITOR`：注册账号，管理自己的报名、预约和新手任务，读取系统消息。
- 成员 `MEMBER`：个人主页、本人任务、悬赏、项目/竞赛参与、讨论互动、积分榜、基金明细和消息。
- 教师 `TEACHER`、核心学生 `CORE_STUDENT`：当前拥有相同的系统管理权限，包括主页、成员、招新、项目、成果、任务、积分及基金管理。教师不参加学生积分排名。

注册不会直接获得成员权限。招新审核转正后，首次进入成员系统会跳到 `/complete-profile` 补学号/内部编号与至少一个能力标签，补全后继续原入口。教师、核心学生的档案由管理端维护。用户名/密码用于登录，内部编号属于成员档案。

## 公开官网与内容编辑

用途：展示实验室、研究方向、成员、项目、成果、新闻和伙伴。入口 `/`；教师/核心学生从后台“主页编辑”进入 `/admin/homepage`。

1. 修改首屏标题、描述、研究方向及其链接、栏目文案、联系外链和公开显示开关。
2. 设置导师/成员/项目的自动或精选范围，调整顺序和数量；实际业务记录仍在各模块维护。
3. 在伙伴栏目维护 Logo、网站和合作介绍；在 3D 模型栏目添加/替换 `.glb`，填写标题、说明、启停与顺序。
4. 模型上传成功后还需要保存主页配置才发布；GLB 2.0、单个最大 20MB、最多 8 项，至少一项启用。内置机器人是带来源许可的演示资源，其他领域可换自己的模型。
5. 点击“保存主页内容”后返回首页确认。名称与 Logo 由源码 `config/branding.json` 统一控制，编辑器保留身份字段展示，其余文案可编辑。

轮播每 8 秒切换，可前后、暂停、重置、拖动/方向键操作；聚焦、悬停或减少动态设置会暂停自动播放。新安装不预填旧实验室的奖项和赞助声明；已经保存的业务内容保持不变。

首页积分总/月/年榜读取账本，每天北京时间零点刷新，公开每榜最多 6 人；登录成员可展开完整分页榜单。基金只公开余额/累计收支。全局日程汇总任务、悬赏、招新、项目和比赛，首页过滤逾期超过 14 天的事项；原记录和个人历史保留。1–2 条静态、3 条以上循环，有暂停/前后和类型筛选。详情权限仍由来源模块控制。

## 成员展示、成员管理与账号

用途：维护身份与公开资料。入口 `/admin/members`（教师/核心学生）、`/profile`、`/profile/edit`（成员身份）、`/members/:profileId`（公开）。

1. 管理员搜索成员、维护姓名、内部编号、专业/班级/年级、内部联系方式、试用/正式状态和能力标签；按界面提供的角色操作管理学生管理员与成员账号。
2. 成员打开“编辑个人主页”，上传头像、填写标语/联系方式/白名单富文本介绍，选择公开项目和已审核奖项并排序。
3. 保存后打开公开主页确认；公开响应不包含内部编号、内部联系方式或内部权限信息。教师不展示学籍和学生积分排名。
4. 个人页可改密码；管理员可重置成员或尚未转正报名者的密码。默认重置值 `OpenLIMS521`，重置会失效该账号的续期会话，需可信渠道通知本人立即改密。

教师与核心学生当前同为系统管理员，不能据角色名称自行假设教师终审。停用的候选/暂停/退出枚举只为历史读取保留，不作为新记录的可选状态。换角色、清理历史数据应遵守服务端限制。

## 招新、面试与转正

用途：从报名到正式成员的审计流程。游客入口 `/application`，管理员入口 `/admin/recruitment`；技能测试子任务为 `/application/subtasks/:subtaskId`。

1. 游客注册、填写并提交自己的报名表，查看处理进度与消息。
2. 管理员初筛，通过后进入面试；发布场次、设置面试官，申请者预约或取消场次。
3. 面试官叫号、开始、记录评分与评价，结论为通过/候补观察/未通过；未到场可移至队尾。候补观察停留在面试，后续由管理员录取或判定未通过。
4. 未录入结论的遗漏记录可转“待补录”，同步结束仍在等待/叫号/面试中的预约。补录前可恢复面试再预约；待补录不能重复预约。
5. 最终面试未通过可由系统管理员撤销到待补录，评价保留、写状态历史并通知；这不适用于其他拒绝阶段。
6. 面试通过进入技能测试，自动关联共享新手大任务；管理员增删子任务即时影响在途申请者。申请者完成所需子任务、提交并等待审核。
7. 审核通过直接转正式成员，没有试用期阶段；转正后首次进入成员系统补学号/编号和能力标签（已完整的档案无需重复填写）。保留报名与面试历史。

进度序列为 `SIGNUP → SCREENING → INTERVIEW → SKILL_TEST → FORMAL_MEMBER`；旧 `PROBATION` 仅用于历史读取，不能恢复为新流程。

## 项目团队

用途：维护真实项目与协作关系。成员入口 `/projects`、`/projects/:projectId`；教师/核心学生通过 `/projects/new` 创建。

1. 系统管理员创建项目、指定负责人，可选教师导师；维护起止日期和状态。
2. 负责人维护团队名称、成员与项目管理员。负责人自动属于成员，项目管理员必须是团队成员；系统管理员可替换负责人。
3. 负责人/项目管理员/系统管理员维护资料、进度、成果、链接和主图（JPG/PNG/WebP，最大 8MB），设置“允许公开展示”。
4. 团队成员读取自己的项目空间，系统管理员可读全部；导师关联本身不自动授予团队管理员权限。
5. 开启公开后才进入公开项目范围，可在主页编辑/个人主页选择展示。私有主图需要参与者或系统管理员的 JWT。

当前项目空间没有即时聊天、群文件或已读消息功能。

## 参赛、竞赛成果与外部新闻

用途：登记团队参赛、记录真实结果、审核成果。成员入口 `/competitions`、`/competitions/new`、`/competitions/:competitionId/edit`；教师/核心学生的成果/新闻入口 `/admin/achievements`。

1. 队长提交一条参赛记录，填写具体比赛名称、比赛日期、队员关联与报名截图；提交者是队长，外部成员姓名可记录但不会自动成为系统账号。
2. 未开始的比赛进入日程；完赛后选择待成绩，或已结束并填写获奖/未获奖。
3. 待成绩、未获奖不强制奖项/证书，不进入公开获奖成果审核，也不能作为竞赛积分来源。
4. 获奖记录填写奖项和证书，可维护图集；管理员审核通过并设置公开展示/顺序，进入成果与关联成员公开主页范围。修改关键资料或替换证书会重新待审核。
5. 私有报名截图仅队长、关联成员、指导教师及管理员读取，公开页面不展示报名文件。真实 PNG/JPEG/WebP 解码和大小校验防止伪装文件。
6. 管理员维护外部新闻的来源、链接、标题与日期，首页按日期展示；新闻引用并不代表已经自动抓取或复制媒体全文。

队长不可通过普通编辑把身份转给别人；公开详情 `/competition-results/:competitionId` 只提供满足公开审核条件的获奖记录。历史进行中/旧获奖记录兼容读取，不猜测成绩与日期。

## 讨论板

用途：公开讨论与成员交流。入口 `/discussions`。匿名/游客只读；成员、教师/核心学生可发帖、回复、点赞并按归属编辑/删除；管理员可处理内容、发布公告和置顶。

选择话题、填写标题与富文本、发布；进入详情回复/点赞或用连续内容编号定位。管理员设置公告/置顶后检查公开列表。公告发布后各角色均不能修改正文/标题。删除不回收内容编号；作者公开动态不泄露内部档案。

## 系统通知与吉祥物

用途：接收报名、审核、任务、积分等业务事件。登录角色入口 `/inbox`，顶栏通知中心可预览/进入消息，读取详情、标记已读或批量已读。

系统“梅琳娜”及可配置吉祥物只发送业务通知，没有用户互相私信接口。教师按账号设置吉祥物、独立文案与展示范围，具体入口见[通知吉祥物设置](notification-mascot-settings.md)。此个性化功能继续保留，不影响消息权限。

## 普通任务与子任务

用途：向指定成员或等级条件人群发任务。管理员 `/admin/tasks`，进度 `/admin/tasks/:taskId/progress`；成员 `/tasks`、`/tasks/:assignmentId`、`/tasks/:assignmentId/subtasks/:subtaskId`。

1. 管理员建草稿，填写说明、等级条件/指定成员、时长及可选积分，按需添加富文本子任务，发布后产生分配。
2. 按人补发通过角色/年级/姓名编号筛选，勾选最终名单，最多 100 人；已发放对象禁选。重试不会重复发放/通知，反馈新增/跳过数量。
3. 成员进入本人任务，按要求提交子任务内容、勾完成情况，提交完成说明；管理员查看进度与提交内容，审核通过或填写驳回意见。
4. 到期判定使用后端有效窗口，统一冻结提交、审核和驳回。审核通过只记录完成，积分由定时器到期后结算，结算时仅给已完成对象；不是审核即发分。

重交窗口由后端结合原截止与驳回后的 24 小时规则计算，页面显示有效期限，不能靠浏览器时间绕过冻结。普通任务没有按人延期入口。

## 共享新手任务

用途：技能测试与直接转正。管理员 `/admin/tasks/onboarding`，申请者在“我的报名”中使用。

管理员维护一个共享大任务、说明、时长和子任务，可批量补发给在途对象；子任务变动即时生效。申请者完成全部要求后提交，管理员审核或以明确豁免理由处理。审核通过转正式成员。新手到期后唯一解锁动作是管理员按人延长截止日期，逾期行提供入口并留下延期历史；完成/已结算对象继续受服务端校验。

## 悬赏与线下奖金履约

用途：成员自愿接取任务，按完成顺序奖励。成员 `/bounties`、`/bounties/:taskId`；管理员 `/admin/bounties`、`/admin/bounties/:taskId/claims`。

1. 管理员设说明、名额上限或不限、奖金总额/获奖人数及可选积分，发布到悬赏榜；不会参与普通任务的等级自动分配。
2. 成员接取、按本人 assignment 提交完成说明，也可在符合条件时放弃。最先完成的 m 人获得奖金资格。
3. 管理员驳回未履约完成者时，奖金顺延给下一位符合条件者；到期后仍受冻结限制。
4. 线下实际发放后，管理员在名单登记“已发放”，获奖者本人确认“已领取”；记录操作者与时间。任务结束/到期仍可补登记。
5. 发放/领取后不能驳回；系统没有奖金台账反向纠错入口。未发放前被驳回可撤销台账并顺延。

台账只记录线下履约，不提供在线支付，不改变完成名次/积分结算。积分仍由到期结算器发给结算时已完成对象，奖金资格与积分分别计算。

## 积分账本、发放与榜单

用途：按真实贡献记录积分。成员 `/points`、个人主页汇总/热力图；教师/核心学生 `/admin/points`。

1. 选择竞赛/项目等来源、库内记录和符合资格的关联正式学生；竞赛要求已结束、获奖且审核通过，项目不受公开开关限制。未绑定系统身份的参赛姓名不能发分。
2. 填事项说明、发生日期、分值/分配。来源编号由后端自动生成，客户端请求键实现重试幂等；新增手工发放不要求凭证链接。
3. 竞赛为每人完整奖项分；其他类型按事项总分分配。实验室贡献每人每月最多 100 分，运营执行与传播效果各 200 分；按实际发生月份封顶，流水同时保留应得/实际分。教师不参与学生榜，管理员不能给自己发分。
4. 发现错误使用整批撤销，填原因，形成反向流水；不能直接改删账本。相同请求不重复记分/通知。
5. 榜单支持总、日、自然周、月、年，同分并列；个人热力图按净积分显示，个人明细最多读取最近 200 笔。首页公开榜仅总/月/年摘要，成员完整榜需认证。

任务积分走独立到期结算，保留旧凭证字段读取兼容，不能用手工积分规则重新定义任务结算时点。

## 实验室基金

用途：单个人民币账户记账与审计。成员 `/fund` 可看汇总及明细，教师/核心学生可操作；访客只能看首页汇总。

管理员先确认期初余额，再登记收入/支出，金额精确到分，填写事项并提交。系统用账户锁、请求键和唯一约束防重复、负余额及重复撤销。错误记录填写撤销原因生成反向流水，保留原流水和操作人/时间。基金没有支付接口、多账户、审批流或对账文件导入；不能将余额理解为银行实收余额。
